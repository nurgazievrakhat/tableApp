# TableEasy

Поиск товаров и сравнение цен по прайс-листам поставщиков в форматах `.xlsx` / `.xls`.
Целевая платформа — Windows. Проект и обоснование решений: [ARCHITECTURE.md](ARCHITECTURE.md).

## Разработка

```bash
npm install
npm run dev
```

`npm run dev` поднимает Vite и запускает Electron; правки в `src/`, `electron/`
и `shared/` пересобираются на лету.

| Команда | Что делает |
|---|---|
| `npm run dev` | Дев-режим с горячей пересборкой |
| `npm run build` | Проверка типов + продакшен-сборка в `dist/` и `dist-electron/` |
| `npm run dist:win` | Сборка установщика `.exe` — **только на Windows или в CI** |
| `npm run check:parser` | Прогон детекта заголовков на образцах прайсов |

## Сборка под Windows

С macOS установщик собрать нельзя: `better-sqlite3` — нативный модуль, ему нужна
компиляция под целевую платформу. Релизы собираются на windows-раннере GitHub
Actions (этап 12). Локально на Mac доступны `dev` и `build` — этого хватает для
всей разработки, кроме выпуска установщика.

## Структура

```
electron/            main-процесс
  main.ts            окно, жизненный цикл, открытие базы
  preload.ts         contextBridge: единственный мост в renderer
  parser/
    values.ts        разбор «грязных» значений: цены, пустые ячейки
    columns.ts       словарь синонимов заголовков и классификация колонок
    detectHeader.ts  поиск строки заголовков настоящего прайса
    readWorkbook.ts  SheetJS: чтение книги, разворот объединённых ячеек
    signature.ts     отпечаток заголовков и маска имени файла
    normalize.ts     нормализация названий, артикулов, единиц
    promo.ts         разбор колонки «Акция» и эффективная цена
    expiry.ts        сроки годности в двух форматах поставщиков
    priceDate.ts     дата прайса из ячейки, имени файла или mtime
    rows.ts          извлечение позиций по профилю, отсев категорий
    worker.ts        utilityProcess: разбор вне main-потока
    service.ts       обёртка над воркером со стороны main
  db/
    connection.ts    соединение, PRAGMA, статус базы
    migrations.ts    раннер миграций по PRAGMA user_version
    migrations/      *.sql, применяются по порядку
    repo/            доступ к данным: поставщики, профили, импорт, поиск
  ipc/handlers.ts    все ipcMain.handle
shared/types.ts      типы, общие для main и renderer
src/                 renderer (React)
```

Renderer к базе напрямую не обращается — только через IPC
(`contextIsolation: true`, `nodeIntegration: false`).

## База данных

Файл: `%APPDATA%/table-easy-app/data.db` (Windows),
`~/Library/Application Support/table-easy-app/data.db` (macOS).

Схема применяется при старте. Версия — в `PRAGMA user_version`; новая миграция
добавляется файлом в `electron/db/migrations/` и строкой в массив `MIGRATIONS`.
Каждая миграция идёт в своей транзакции.

Сбросить базу в разработке — просто удалить файл, схема пересоздастся при запуске.

## Парсинг таблиц

`xlsx` ставится не из npm-реестра, а с CDN SheetJS — в npm застряла версия
0.18.5 с известными CVE, поэтому в `package.json` прописан прямой URL на 0.20.3.
Это единственная зрелая JS-библиотека, читающая и `.xlsx`, и старый `.xls`.

Разбор идёт в отдельном процессе (`utilityProcess`): прайс на 5930 строк — это
около 420мс, на 100k строк уже секунды, и в main-потоке это заморозило бы окно.

`npm run check:parser` прогоняет детект заголовков на образцах и сверяет
результат с ожидаемым. Свои файлы: `node --no-warnings scripts/check-parser.mts <файл>`.

## Профили поставщиков

Разметка колонок сохраняется как профиль и в следующий раз применяется сама.
Файл опознаётся по **составному ключу**: отпечаток строки заголовков (sha1 от
нормализованных названий колонок) плюс маска имени файла, выведенная
автоматически — `Прайс Фармамир от 18.08.26.xls` → `Прайс Фармамир от *.xls`.

Отпечатка одного мало: выгрузки из 1С у разных поставщиков дают одинаковую
шапку. Если отпечаток совпал с несколькими профилями, а имя файла их не
разводит, приложение не угадывает, а просит выбрать поставщика.

## Импорт

Идёт по сохранённому профилю, одной транзакцией. Повторный импорт не создаёт
дублей: позиции находятся по `item_key` и обновляются, а в `price_history`
попадают только фактически изменившиеся цены. Позиции, пропавшие из нового
прайса, гасятся (`is_active = 0`), а не удаляются — история остаётся.

Файл с уже загруженным содержимым отклоняется по sha1: так отсекается
повторно скачанный `прайс (2).xlsx`.

## Поиск

Идёт по FTS5-индексу сразу по всем прайсам: на 8358 позициях запрос занимает
единицы миллисекунд. Порядок слов не важен, каждое слово ищется по префиксу.

Дозировку можно писать и слитно, и через пробел — `100 мкг` и `100мкг`
нормализуются одинаково. Если запрос не нашёл ничего, слова сверяются со
словарём самих прайсов и опечатка исправляется: `аэртл` → `аэртал`. Сокращения
при этом не трогаются — `церебр` остаётся префиксным поиском.

## Источники

Вкладка «Источники» показывает загруженные прайсы и состояние каждого файла на
диске: `актуален`, `изменился`, `пересохранён` (дата правки другая, содержимое
то же), `заменён` (позиции перешли к более свежему прайсу поставщика) и
`файл не найден`.

Сравнение двухшаговое: сперва `mtime`, и только при расхождении считается sha1 —
чтобы отличить настоящую правку от простого пересохранения в Excel.

Удаление источника уносит его позиции и историю, но оставляет профиль разметки.

## Автоподхват из папки

Вкладка «Папки» назначает каталоги, куда складываются прайсы. Файл, попавший
туда, разбирается сам:

- содержимое уже загружено — пропускается молча;
- поставщик опознан по отпечатку заголовков — импортируется без вопросов;
- профиль не найден или отпечаток совпал с несколькими — файл уходит в очередь
  «требуют разметки». Приложение не угадывает.

Разметив такой файл один раз, следующий прайс того же поставщика приложение
загрузит само. Обход папок идёт и при запуске — прайсы, положенные пока
программа была закрыта, не теряются.
